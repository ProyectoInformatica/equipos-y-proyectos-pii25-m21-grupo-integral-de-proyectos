INTEGRACION COMPLETA ESP32 WIFI + APP PYTHON (FLET) + MYSQL
============================================================

Objetivo
--------
Tener una maqueta con ESP32 conectada por WiFi que:
1) Envie lecturas de sensores al sistema Python.
2) Reciba comandos de actuadores (luces, barreras) y configuraciones (umbrales, horario).
3) Permita controlar todo desde la app Flet en un PC de la misma red.


Docker vs MySQL vs JSON (aclaracion importante)
-----------------------------------------------
- Docker:
  Es la forma de ejecutar servicios en contenedores. En tu caso, puede ejecutar MySQL.

- MySQL:
  Es la base de datos real donde se guardan los datos (sensores, estados, umbrales, etc.).

- JSON:
  Es solo el formato de intercambio de datos por red entre ESP32 y backend Python.
  NO reemplaza a MySQL ni a Docker.

Flujo real:
ESP32 <---JSON/HTTP---> wifi_bridge.py ---> MySQL (puede estar dentro de Docker)


Arquitectura final
------------------
- ESP32 (firmware):
  - Lee sensores.
  - Hace POST de telemetria al puente WiFi Python.
  - Hace GET periodico para obtener comandos/configuracion.

- Proyecto Python:
  - App Flet (app.py): interfaz de usuario para modificar estados/umbrales.
  - database.py: acceso a MySQL.
  - wifi_bridge.py: API local HTTP para intercambio con ESP32.
  - run_system.py: arranca procesos segun modo simulacion/real.

- MySQL:
  - Guarda sensores, estados, configuraciones y notificaciones.


Ejemplo rapido: MySQL dentro de Docker
--------------------------------------
Si tu base de datos esta en Docker, debes asegurar:
1) Que el contenedor de MySQL este levantado.
2) Que exponga el puerto (normalmente 3306).
3) Que config.py apunte a ese host/puerto/credenciales.

Ejemplo docker-compose (referencia):

services:
  mysql:
    image: mysql:8.0
    container_name: smart_mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: smart_residencial
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:

Con este ejemplo, en config.py suele quedar:
- MYSQL_HOST = "localhost"
- MYSQL_PORT = 3306
- MYSQL_USER = "root"
- MYSQL_PASSWORD = "rootpassword"
- MYSQL_DB = "smart_residencial"


Cambios implementados en el proyecto
------------------------------------
1) Se creo el archivo:
   - wifi_bridge.py
   Endpoints disponibles:
   - GET  /health
   - POST /telemetry
   - GET  /command

2) Se actualizo:
   - run_system.py
   Logica nueva:
   - Si MODO_SIMULACION=True => arranca sensores simulados.
   - Si MODO_SIMULACION=False y ESP32_USE_WIFI=True => arranca wifi_bridge.py.
   - Si MODO_SIMULACION=False y ESP32_USE_WIFI=False => arranca serial_bridge.py.

3) Se actualizo:
   - config.py
   Nuevas variables:
   - BRIDGE_HOST
   - BRIDGE_PORT
   - ESP32_API_KEY
   - ESP32_DEVICE_ID


Configuracion necesaria (paso a paso)
-------------------------------------
1) MySQL
   - Asegura que el servidor MySQL este encendido.
   - Verifica credenciales en config.py:
     MYSQL_HOST, MYSQL_PORT, MYSQL_USER, MYSQL_PASSWORD, MYSQL_DB

2) Modo real ESP32 WiFi
   En config.py poner:
   - MODO_SIMULACION = False
   - ESP32_USE_WIFI = True
   - BRIDGE_HOST = "0.0.0.0"
   - BRIDGE_PORT = 8765 (o el puerto que prefieras)
   - ESP32_API_KEY = "clave-segura"

3) Red local
   - PC y ESP32 en la misma red WiFi.
   - Desde ESP32 debe poder alcanzarse la IP del PC.
   - En Windows, permitir en firewall el puerto BRIDGE_PORT para Python.

4) Dependencias Python
   - pip install -r requirements.txt


Contrato HTTP para el firmware ESP32
------------------------------------
IMPORTANTE:
- Enviar cabecera: X-API-Key: <ESP32_API_KEY>
- Content-Type: application/json

1) POST /telemetry
   URL ejemplo:
   - http://IP_DEL_PC:8765/telemetry

   JSON de entrada (ejemplo):
   {
     "device_id": "esp32-maqueta-1",
     "temperatura": 28.4,
     "humedad": 61.0,
     "calidad_aire": 120.5,
     "humo": 8.2,
     "luminosidad": 330.0,
     "distancia_norte": 42.0,
     "distancia_sur": 53.0,
     "caudal": 2.6,
     "viento": 11.2
   }

   Respuesta esperada:
   {
     "ok": true,
     "saved_fields": 9
   }

2) GET /command
   URL ejemplo:
   - http://IP_DEL_PC:8765/command?device_id=esp32-maqueta-1

   Respuesta ejemplo:
   {
     "ok": true,
     "command": {
       "timestamp": 1714400000,
       "led": true,
       "barrera_norte": false,
       "barrera_sur": false,
       "thresholds": {
         "temp_max": 35.0,
         "hum_min": 30.0,
         "hum_max": 70.0,
         "iaq_max": 100.0,
         "humo_max": 25.0,
         "viento_max": 50.0
       },
       "schedule": {
         "hora_inicio": 18,
         "minuto_inicio": 0,
         "hora_fin": 6,
         "minuto_fin": 0
       },
       "device_id": "esp32-maqueta-1"
     }
   }

3) GET /health
   URL ejemplo:
   - http://IP_DEL_PC:8765/health

   Uso:
   - Ver estado del puente y edad de ultima telemetria recibida.


Recomendacion de loop en ESP32
------------------------------
Cada 2 a 5 segundos:
1) Leer sensores.
2) POST /telemetry con JSON.
3) GET /command.
4) Aplicar salidas:
   - command.led => rele/led luces.
   - command.barrera_norte / command.barrera_sur => servo/motor.
5) Reintento con backoff simple si hay error de red.


Como arrancar el sistema
------------------------
1) Verificar config.py en modo real WiFi.
2) Ejecutar:
   - python run_system.py
3) El sistema levantara:
   - wifi_bridge.py
   - controladores (alarmas, scheduler, etc.)
   - app.py (interfaz Flet)


Validaciones funcionales recomendadas
-------------------------------------
1) Comprobar bridge:
   - GET /health responde 200.

2) Comprobar telemetria:
   - Enviar POST /telemetry de prueba y revisar que cambien datos en vistas.

3) Comprobar comandos:
   - Cambiar luz desde la app.
   - En la siguiente llamada GET /command debe cambiar "led".

4) Comprobar umbrales:
   - Cambiar umbral en la app.
   - Verificar en GET /command -> thresholds actualizado.

5) Comprobar horario:
   - Cambiar horario de iluminacion en la app.
   - Verificar en GET /command -> schedule actualizado.


Checklist de despliegue para maqueta
------------------------------------
- [ ] ESP32 con IP fija o reserva DHCP.
- [ ] PC y ESP32 en misma red.
- [ ] Puerto BRIDGE_PORT permitido en firewall.
- [ ] MODO_SIMULACION=False.
- [ ] ESP32_USE_WIFI=True.
- [ ] Misma API key en ESP32 y config.py.
- [ ] Prueba de telemetria correcta.
- [ ] Prueba de actuadores correcta.


Notas importantes
-----------------
- El control por WiFi implementado usa patron "pull" para comandos:
  ESP32 pregunta periodicamente /command.
  Esto simplifica la red y evita problemas de NAT/firewall al enviar desde PC a ESP32.

- Si prefieres patron "push" (backend envia directo a ESP32), se puede extender despues.

- Si usas solo una barrera fisica, puedes ignorar barrera_sur.
